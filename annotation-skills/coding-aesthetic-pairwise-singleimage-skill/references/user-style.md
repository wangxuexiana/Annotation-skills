# User Style

Use this file as the first source for reason wording when the user provides historical annotation answers.

## Default Style

- Keep reasons compact, usually one short sentence.
- Use natural Chinese and visible evidence.
- Prefer concrete terms such as 层级, 配色, 排版, 素材, 统一, 可读性, 场景.
- Avoid formal audit language and over-polished wording.
- Avoid claiming hidden functionality or implementation quality.
- Use punctuation required by the current platform. If the user gives a punctuation preference, treat it as a hard rule.
- 2026-06-11 user hard rule: annotation reasons may use commas only. Do not use periods, semicolons, enumeration commas, colons, slashes, parentheses, quotes, or other punctuation in overall or dimension reasons.
