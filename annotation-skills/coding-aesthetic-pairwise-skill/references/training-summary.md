# Training Summary

## 任务与队列

- 任务名称：Coding 美观度 pairwise / Coding 美学 pairwise。
- 资料来源：
  - https://bytedance.larkoffice.com/wiki/EQGTwSnjWiBWUkkCdXFc3Fbzntc
  - https://bytedance.larkoffice.com/wiki/MuY9wfnJbizKBykRDIacBoz2nue
- 目标：评估两个模型在同一 prompt 下生成的网站产物截图的美观度表现。
- 对象：repo_0 与 repo_1 的截图。URL 只用于验证截图是否合理，不直接用于判断网页质量。

## 核心判定

- 本任务只根据截图判断网页美观度。
- 不考虑网站功能完整性、交互逻辑、按钮能否点击、页面流程是否可用。
- 不以截图数量定胜负，只根据截图内容的美观度和整体观感判断。
- 如果截图无法反映 prompt 要求的关键标签或内容，选择废弃并在备注说明，不填写 -1、0、+1 评分。
- 总体评价使用 -1、0、1：-1 表示模型 1 更美观，0 表示两者相当，1 表示模型 2 更美观。

## 美观度维度

- 重点看布局、颜色、素材是否精致。
- 配色过于鲜艳、廉价、刺眼会降低美观度。
- 颜色对比度以文字能看清、必要信息突出为宜，不是越强越好。
- 素材优先高级、精致、统一，例如 SVG 风格素材通常优于系统原生 emoji。
- 多截图场景要看整套页面的统一性和协调性。
- 不要因为页面留白、简约就直接判差，要综合视觉舒适度、信息密度和一致性。

## 操作流程

1. 先读 prompt。
2. 查看两组截图，先判断是否废弃。
3. 只在需要验证截图合理性时查看 URL。
4. 填写推荐维度说明和总体评价。
5. 最后查重或完成平台要求的收尾操作。

## 易错点

- 不要按截图数量多的一方判胜。
- 不要因为需求要求首页信息页，而截图没包含首页，就直接按功能缺失扣分；仍优先看已有截图的美观度。
- 两边都差时，如果差距不明显可判 0；如果一方相对明显更美观，可以选相对更好的一方。
- 局部裂图、局部素材异常可能扣分，但要看是否影响整体美观度。
- 语言不一致属于一致性问题，可影响美观和完整观感。
- 遇到白屏、报错、黑屏、截图无法判断等情况，按废弃处理。

## 理由话术

- GSB 对比描述要尽量详细，说明具体美观差异。
- 理由应围绕布局、配色、素材、统一性、视觉舒适度、信息层级等截图可见证据。
- 不写功能交互是否可用，除非只是说明“不作为本任务判断依据”。
