# Training Summary

## 任务与队列

- 任务名：Coding 美观度 pairwise 标注，SingleImage 单图版本。
- 材料来源：
  - Wiki 手册：`https://bytedance.larkoffice.com/wiki/Km1NwuQ4Aio91ckSKs1cnNLcnzb`
  - 培训妙记：`https://bytedance.larkoffice.com/minutes/obcnzvff41l1jt7y85v61u3f`
- 任务形式：同一 prompt 下对两个模型各一张网页截图做美观度对比，判断模型 1 / 模型 2 / same。
- 当前版本重点：本任务只通过截图判断网页美观度，不考虑功能交互与完整性。

## 核心判定

- 先判断截图是否足以给出美观度优劣结论。能判断则正常评测；不能通过截图判断则废弃。
- 先根据截图内容和布局推断页面用途，并在标注模板下拉框选择用途，例如 SaaS 着陆页、数据仪表盘、博客文章、电商产品页、工具表单等。
- 再按四个维度综合判断：布局与信息层级、色彩与排版、图像图标与素材质量、一致性与细节精致度。
- 三个核心原则优先于具体维度：
  - 致命缺陷优先于轻微瑕疵。
  - 场景目标优先于个人审美风格。
  - 进取式优质执行优先于保守式无错设计。
- 差异不明显、双方各有优劣且无法稳定判断时，选 same，不要强行分胜负。
- 不能把内容空洞、元素单一、布局单调误判为简洁高级；有内容、有优质素材、有统一细节且完成度高的页面优先。

## 标注值

- `-1`：模型 1 更美观。
- `0`：两者美观度基本相当。
- `1`：模型 2 更美观。

## 废弃规则

- 无法通过首帧/截图判断美观度，废弃。
- 截图明显没截好，信息太少，主体缺失或裁切到无法判断，废弃。
- 白屏、黑屏、乱码、报错，废弃。
- 图片与 URL 或产品状态不对应到无法判断当前产物，可废弃。
- 原始数据截图存在质量问题时，需要记录到特殊 case 维护文档。
- 废弃数据不给结算。

## 操作流程

1. 阅读 prompt，点击“我已阅读 prompt”后解锁标注项。
2. 观察两个模型截图；必要时使用页面提供的放大图功能。
3. 不需要打开 URL 测功能，URL 主要用于证明截图是否对应当前产物。
4. 选择页面用途下拉框。
5. 对四个维度分别描述优劣，尽量具体写出哪个维度哪边好或不好。
6. 给出总体分数 `-1 / 0 / 1` 和总体描述。
7. 若是废弃题，按废弃原因处理，并记录特殊 case。

## 易错点

- 只评美观度，不评功能是否可交互或需求是否完整实现。
- 不要因为一个页面更“内容多”就直接判优；内容必须贴合场景且视觉统一。
- 不要因为一个页面更“极简”就直接判优；空洞单调不是高级。
- 核心文字无法阅读、核心按钮无法辨识、核心素材遮挡或破损属于致命缺陷，优先级很高。
- 页脚、版权、辅助小字等非核心内容轻微偏小或模糊一般不大幅扣分。
- 高饱和颜色不是看见鲜艳就判错；要看是否大面积刺眼、廉价、色彩轰炸，或与场景不匹配。
- 时尚风格、儿童教育等场景可以使用更鲜艳的风格，前提是整体协调。
- 两轮盲标机制下，A/B 两位标注一致才直接进入验收；不一致会由第三位复核。

## 理由话术

- 理由要围绕截图可见证据，不写功能测试结论。
- 需要写得比普通短理由更细一点，至少覆盖关键维度差异；培训中特别强调“每个维度哪好哪不好”。
- 推荐自然中文，直接指出布局、配色、素材、文字可读性、一致性等差异。
- same 的理由说明双方整体接近，或问题程度相近，没有稳定优劣。

## 问卷知识点

- 本任务只通过截图判断美观度，不考虑功能交互与完整性。
- 无法通过截图判断美观度时废弃。
- 评分值：`-1` 模型 1 更美观，`0` 基本相当，`1` 模型 2 更美观。
- 四个维度：布局与信息层级、色彩与排版、图像图标与素材质量、一致性与细节精致度。
- 三个核心原则：致命缺陷 > 轻微瑕疵；目标与情境 > 个人风格；有雄心的执行 > 保守的执行。
- 差异不明显时选 same，不强行比高低。
- 白屏、黑屏、乱码、报错、截图质量不足属于废弃候选。
