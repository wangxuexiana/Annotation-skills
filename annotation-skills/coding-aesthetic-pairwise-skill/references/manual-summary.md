# Manual Summary

## Coding美观度pairwise标注手册丨0515

- 正式作业前必须严格按手册规范作业，标注质量关联结算。
- 任务用于评估两个模型生成的网站产物在同一 prompt 要求下的美观度表现。
- 标注员需结合两组网站截图，对 repo_0 与 repo_1 的美观度进行对比判断。
- 只通过截图判断网页美观度，网站 URL 仅用于验证截图是否不全或截得不合理。
- 不考虑功能交互与完整性。
- 胜负不以截图数量为准，只依据截图内容美观度评判。
- 当仅通过截图无法判断时，统一废弃并备注说明。
- 领取单条数据超过 60 分钟自动释放；返修数据 18 小时不处理自动释放。
- 废弃数据不结算。

## Coding美学pairwise规则迭代丨0519

- 美观度更看重布局、颜色、素材是否精致，部分细节不影响整体判断。
- 过于鲜艳、廉价、刺眼的配色会降低美观度。
- 颜色对比度以看清文字、突出必要信息为宜，并非越强越好。
- 素材优先选择高级精致的 SVG 格式，不优先原生 emoji。
- 原生 emoji 是 Unicode 字符，依赖系统字体渲染，不同系统显示不同。
- SVG emoji 是页面自己渲染的矢量图形，相对更统一、更可控。
- 多截图场景需兼顾整体观感，不宜否定留白简约设计。
- 多图判断要保障整套页面设计风格统一协调，综合考虑内容丰富度与视觉舒适度。
- 截图无法反映 prompt 要求标签时，应在备注说明“截图无法反应那个标签”，无需填写 -1、0、+1，按废弃处理。
- 废弃 case 包括白屏、报错、黑屏等无法正常判断截图美观度的情况。
