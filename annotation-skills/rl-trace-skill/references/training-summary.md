# RL Trace Training Summary

## 任务与队列

- 任务名称：RL Trace 标注手册
- 队列/平台：Visual Coding 草图/复刻-0617，AIDP Lite task `7652321716413075250`
- 作业链接：https://aidp-lite.bytedance.net/management/task-v2/7652321716413075250/data-dashboard
- 单条数据包含同一任务的两个候选结果 A 和 B，需要结合 prompt、参考图、截图、HTML、visual rubrics、function rubrics 完成判断。

## 核心判定

- 先看 `prompt`，再看参考图，再分别判断 A 和 B。
- 任务类型三选一：复刻（含流程图）、草图、无法判断。
- 复刻任务：重点看候选是否更接近参考图，不因为某个候选单纯更好看就给高分。
- 草图任务：重点看是否把低保真草图产品化为真实高保真网页，而不是机械照抄 wireframe。
- 是否有明确功能要求只看 prompt，不因页面上出现按钮、输入框、导航就脑补功能要求。
- Visual Rubric 优先看截图，必要时打开 HTML 辅助确认。
- Function Rubric 一律打开 HTML 实际操作，不要只看截图。
- 仅视觉 GSB 只比较视觉质量，不能把功能问题算进去。
- 整体 GSB 比较视觉加明确功能要求；没有明确功能要求时通常接近视觉 GSB。

## 标注流程

1. 看 `prompt`。
2. 看参考图。
3. 判断任务类型：复刻 / 草图 / 无法判断。
4. 判断是否有明确功能要求。
5. 看 A/B 截图，标 visual rubrics。
6. 如果有功能要求，或 function rubrics 不为空，打开 A/B HTML 实际操作，标 function rubrics。
7. 填写仅视觉 GSB。
8. 填写整体 GSB。
9. 如果关键材料打不开，按规则填无法判断或废弃，并写备注。

## 任务类型识别

- 复刻：prompt 有“复刻”“1:1 还原”“根据参考图还原页面”等，参考图像完整网页成品图。判断候选是否更接近参考图。
- 草图：prompt 有“根据草图 / 线框图 / wireframe / 低保真图生成网页”等，参考图是结构图、手绘图或占位块图。判断候选是否产品化。
- 无法判断：prompt 太模糊或材料不足，备注写原因。

## 功能要求识别

- 标“是”：prompt 明确要求点击、切换、展开、弹窗、Tab、轮播、筛选、排序、输入、提交、校验、导航跳转、hover、响应式、mock 请求等。
- 标“是”：prompt 虽未点名具体控件，但出现“自然反馈”“交互反馈”“状态反馈”“正常作业”“正常运行”等需要实际操作验证的描述。
- 流程图题目同样适用：只要 prompt 提到节点点击、展开/折叠、hover 提示、切换高亮、跳转联动或正常运行，就打开 HTML 实测。
- 标“否”：只要求视觉还原、布局、配色、文案、组件呈现，没有要求真实可操作行为。
- 标“无法判断”：prompt 含糊，或材料打不开导致无法判断。

## Rubric 评分

- 1：满足该 rubric 的核心要求。
- 0：不满足，或只做出表层样子但关键内容缺失。
- 无法判断：视口看不到、需要登录或权限、信息不足。
- Visual 1：核心模块在，布局大体对，文本和风格基本落地，小差异不影响主要判断。
- Visual 0：关键模块缺失、位置明显错、主要内容不对、白屏报错、严重跑版；草图任务保留线框/灰块/占位内容通常为 0。
- Function 1：交互入口存在，操作后有正确反应，输入、提交、校验、筛选、排序、Tab、弹窗、轮播、导航等能跑通。
- Function 0：只有样子没有真实交互，点击结果错误，核心功能缺失，操作后报错或页面崩坏。

## GSB 规则

- GSB 永远判断 A 相对 B。
- 仅视觉 GSB：只看视觉目标达成，不纳入功能。
- 整体 GSB：视觉加明确功能要求；核心功能缺失会显著影响整体 GSB。
- 可选值：good = A 明显更好，same = A 和 B 差不多，bad = A 明显更差。
- 无明确功能要求时，整体 GSB 通常跟视觉 GSB 接近。
- 有明确功能要求时，如果 A 更好看但核心功能不通，B 稍丑但功能完整，整体可判 A bad。
- 功能只是轻量附加项且视觉差距巨大时，整体 GSB 可主要跟随视觉判断。

## 废弃与异常

- 截图打不开但 HTML 能打开：废弃并备注。
- HTML 打不开但截图能打开：废弃并备注。
- 截图和 HTML 都打不开：废弃并备注。
- 白屏或严重报错：相关 visual rubric 通常标 0；若另一候选正常，视觉 GSB 通常正常方更好；两边都白屏时视觉 GSB 往往 same。
- 长页面或截图只到首屏：先按首屏判断，需要时打开 HTML 补充检查；仍看不到的内容单项标无法判断。

## 易错点

- 不要把功能问题算进仅视觉 GSB。
- 不要只看截图就给 function rubric 打分。
- 不要因为页面出现按钮、输入框、导航就自动评功能。
- 草图任务不能照抄成 wireframe。
- 草图任务保留 Lorem ipsum、Placeholder、灰块、箭头、批注、线框风格通常要扣分。
- 如果参考图展示 hover、弹窗、选中、展开等状态，但 prompt 没要求真实触发链路，只按视觉状态还原评价，不自动扩展为功能评测。

## 理由话术

- 理由应短、自然、直接，围绕主决定证据。
- 推荐句式：
  - `UP 无明确功能要求，function 不参与整体 GSB。`
  - `A 视觉更接近参考图，但 B 完成核心筛选交互；整体判 B 更好。`
  - `两者都保留大量 Placeholder，视觉 same。`
  - `参考图为草图，按草图任务评价，A 产品化更完整。`

## 问卷知识点

- 标注顺序：prompt -> 参考图 -> 任务类型 -> 功能要求 -> visual rubrics -> function rubrics -> 视觉 GSB -> 整体 GSB。
- 复刻看像不像参考图。
- 草图看有没有把低保真图做成成品网页。
- 功能只看 prompt 明确要求的部分。
- 自然反馈、交互反馈、状态反馈、正常作业、正常运行都属于功能要求。
- Function rubric 必须打开 HTML 实测。
- 仅视觉 GSB 不能考虑功能。
