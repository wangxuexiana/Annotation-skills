## 必填内容

每条数据包含同一任务两个候选结果 A 和 B，需要完成：

1. 判断任务类型：复刻（流程图）/ 草图 / 无法判断。
2. 判断是否有明确功能要求：是 / 否 / 无法判断。
3. 给 A、B 分别标注每条 visual rubric。
4. 给 A、B 分别标注每条 function rubric。
5. 填写两个 GSB：仅视觉 GSB 和 整体 GSB。

## 标注顺序

1. 看 `prompt`。
2. 看参考图。
3. 判断任务类型。
4. 判断是否有明确功能要求。
5. 看 A/B 截图标 visual rubrics。
6. 如果有功能要求，或 function rubrics 不为空，打开 A/B HTML 实操并标 function rubrics。
7. 填视觉 GSB。
8. 填整体 GSB。
9. 关键材料打不开时，按规则填无法判断或废弃，并写备注。

## 任务类型规则

- 复刻：prompt 包含复刻、1:1 还原、根据参考图还原页面等，参考图像完整网页成品图。核心是候选是否更接近参考图。
- 草图：prompt 包含根据草图、线框图、wireframe、低保真图生成网页等，参考图是结构图、手绘图、占位块图。核心是候选是否把低保真草图产品化。
- 无法判断：prompt 模糊或材料不足。

## 明确功能要求规则

- 只看 prompt 明确提出的功能。
- 明确要求点击、切换、展开、弹窗、Tab、轮播、筛选、排序、输入、提交、校验、导航跳转、hover、响应式、mock 请求等，标“是”。
- prompt 出现自然反馈、交互反馈、状态反馈、正常作业、正常运行等，也标“是”，需要实际操作验证。
- 流程图题目不默认只看静态样式；只要 prompt 提到节点点击、展开折叠、hover 提示、切换高亮、跳转联动、正常作业或正常运行，就打开 HTML 实测。
- 仅视觉还原、布局、配色、文案、组件呈现，没有真实可操作行为要求，标“否”。
- prompt 含糊或材料打不开，标“无法判断”或废弃。

## Visual Rubric

- 优先看截图，必要时打开 HTML 辅助确认。
- 标 1：核心模块在，布局大体对，文本和风格基本落地，小差异不影响核心判断。
- 标 1：复刻任务位置、比例、内容、颜色、层级与参考图大体接近。
- 标 1：草图任务正确理解草图模块，并转为真实高保真网页内容。
- 标 0：核心模块缺失、位置明显错误、内容严重不符。
- 标 0：页面白屏、明显报错、布局大面积塌陷、主要内容不可读。
- 标 0：复刻任务新增大量参考图没有的大模块、广告、弹窗或无关内容。
- 标 0：草图任务保留 wireframe、Lorem ipsum、Placeholder、灰块图片、手写批注、箭头说明等。
- 标无法判断：rubric 要求内容在截图外，且 HTML 也无法确认。

## Function Rubric

- 一律打开 HTML 实际操作，不要只看截图。
- 标 1：交互入口存在，事件绑定正确，操作后状态或视图合理变化。
- 标 1：表单可输入，提交、校验、反馈可观察。
- 标 1：筛选、排序、Tab、轮播、弹窗、导航等行为符合 UP 核心要求。
- 标 1：mock 请求、加载、成功或失败结果有可见状态。
- 标 0：只有按钮或控件样子，点击无状态变化。
- 标 0：交互链路断裂，比如可点击但结果不更新、弹窗无法关闭、筛选结果错误。
- 标 0：UP 要求的核心功能缺失。
- 标 0：操作后页面报错、布局崩坏、内容丢失。
- 标无法判断：交互需要外部服务、登录、权限，或 rubric 不清楚。
- function rubrics 为空时，通常不需要逐条标功能，整体 GSB 主要看视觉和页面完成度。

## GSB

- GSB 永远判断 A 相对 B。
- 仅视觉 GSB 只看视觉质量，不能把功能算进来。
- 整体 GSB 看视觉和明确功能要求。
- 可选值：good = A 明显更好；same = A 和 B 差不多；bad = A 明显更差。
- same 常见场景：两者都很好且只有小颜色、间距、文案差异；两者都很差；A/B 各有明显优劣且稳定优劣难判；差异只在次要细节。
- 无明确功能要求时，整体 GSB 通常接近视觉 GSB。
- 有明确功能要求时，先看视觉结构，再看功能是否真实可用。
- 核心功能缺失会显著影响整体 GSB。
- 功能非常核心时，A 视觉略好但大量核心交互不可用，B 视觉稍差但功能完整，整体可给 A bad。
- 功能只是轻量附加项时，视觉差距巨大可主要跟随视觉判断。

## 草图评分维度

- 草图视觉顺序：布局还原 -> 内容填充 -> 产品化完成度 -> UP 风格要求。
- 布局还原：模块数量、分区、相对位置、层级、信息流是否符合草图。
- 内容填充：占位文字、灰块、图片框、假文、注释是否替换为符合 UP 主题的真实内容。
- 产品化完成度：配色、字体、间距、圆角、阴影、图片、图标是否像正常高保真网页。
- 草图功能顺序：核心功能是否存在 -> 操作链是否跑通 -> 结果是否正确 -> 反馈是否清晰 -> 交互后页面是否稳定。

## 复刻评分维度

- 复刻视觉顺序：布局与空间关系 -> 元素完整性 -> 内容准确性 -> 视觉还原度 -> 幻觉控制。
- 布局与空间关系：整体版式、位置、尺寸比例、对齐、间距、首屏可见内容是否接近参考图。
- 元素完整性：核心区块、导航、卡片、按钮、图标、图片、图表、背景装饰是否完整。
- 内容准确性：文字、数字、标签、按钮文案、价格、日期、图表语义是否准确。
- 视觉还原度：颜色、字体、字号、字重、圆角、阴影、边框、背景、纹理、留白、层级是否接近。
- 幻觉控制：是否新增参考图没有的大模块、广告、弹窗、导航、图片或无关文案。
- 复刻功能顺序：UP 功能完整性 -> 交互链路正确性 -> 与参考图状态一致 -> 不破坏还原。

## 特殊情况

- 截图打不开但 HTML 能打开：废弃并备注。
- HTML 打不开但截图能打开：废弃并备注。
- 截图和 HTML 都打不开：废弃并备注。
- 白屏或严重报错：相关 visual rubric 通常标 0；另一候选正常时视觉 GSB 通常正常方更好；两边都白屏时视觉 GSB 往往 same。
- 长页面或截图只到首屏：先按首屏判断，需要时打开 HTML 补查；仍看不到的内容单项标无法判断。

## 提交前检查

- 任务类型已填写。
- 是否有明确功能要求已填写。
- 每条 visual rubric 的 A/B 都已打分。
- 如果有功能要求或 function rubrics 非空，每条 function rubric 的 A/B 都已打分。
- 视觉 GSB 已填写为 good / same / bad。
- 整体 GSB 已填写为 good / same / bad。
- 凡是无法判断、打不开、白屏、材料异常的地方，都写了备注。
