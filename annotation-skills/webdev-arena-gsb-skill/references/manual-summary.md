# Manual Summary

## 官方规则

- 手册目标：统一 WebDev Arena 回流数据逐局盲评的「是否可正常查看」「GSB 判定」「详细评价」。
- 对比对象：匿名展示的「产物模型一 / 产物模型二」最终产物。
- 判断依据：当前局最终产物、完整题目要求、用户输入图/素材、两个产物预览链接。
- 不允许猜模型，不参考已有胜负结果。

## 标注前检查

- 阅读全部轮次用户消息，并结合中文摘要理解完整需求。
- 检查用户输入图、logo、设计稿、参考图等素材是否被正确使用。
- 打开 A/B 预览链接查看最终网页效果和功能。
- 先确认两边是否可正常访问，是否白屏、报错、空白页或明显构建失败。

## GSB 标签

- G：模型一明显更好。
- S：两者相当，包括同样好或同样差。
- B：模型一明显更差，即模型二明显更好。

## 废弃与可查看性

- 两个产物都无法正常加载、无法正常显示内容时，题目废弃。
- 两个候选产物只有一个无法正常加载时，题目正常作业，不废弃。
- 单边加载失败时，应在理由中描述无法正常加载的一边，并继续评价可加载的一边是否满足 prompt。

## 特殊题型

- 题目要求实现脚本内容和参考图中圆环增加旋转时，只看视觉效果，脚本内容忽略。
- 网页复刻题中，参考图非完整题目时，按完整网页进行复刻和评估；不能因为参考图只展示首屏就把只做首屏视为完整。

## 理由写法

- 必须写一段详细中文评价，说明为什么给该 GSB。
- 评价中要指出模型一和模型二各自的优缺点，以及最关键差距。
- 推荐结构：标签结论，更好方优势，较差方问题，关键差距，和题目需求的对应关系。

## 评价维度

- 视觉美观与还原度：布局、间距、尺寸、颜色、字体、组件形态、参考图还原。
- 功能交互：需求中指定的按钮、弹窗、动画、控件、交互是否正常实现。
- 内容数据：文案、数据、业务语义是否匹配题目，不使用空泛模板化内容。
- 素材处理：图片、logo、设计稿、参考图是否正确使用。
- 完成度：整体是否做完，是否存在白屏、报错、局部未渲染、关键模块缺失。
- 指令遵循：完整多轮需求和最后一轮修改点是否落实。
