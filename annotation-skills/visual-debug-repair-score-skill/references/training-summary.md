# Visual Debug 修复评分训练摘要

## 任务与队列

- 任务名称：Visual Debug 标注手册，新工艺队列。
- 作业平台：AIDP Lite。
- 队列链接：VLM Coding 新工艺-0705，任务 ID `7658870044009008946`。
- 单题价格：标注 7 元，质检 3 元。
- 任务目标：评估模型对视觉问题的修复效果，判断模型是否按 Prompt 中的问题描述完成修复，并检查修复后的网页产物与参考图的一致性。

## 核心判定

- 先理解 Prompt 或问题修复描述要修什么，再打开网页产物核对修复是否完成，最后看与参考图的视觉还原度。
- 命中废弃规则时不进入 0/1/2 分。
- 正常评分优先级：废弃判断 > 页面是否可正常展示 > 核心问题是否修复 > 参考图还原度 > 多个 2 分候选的唯一判定。
- 0 分：核心问题没有修好，或网页产物加载不出来、一直加载、无法正常查看。
- 1 分：核心问题已修复，但与参考图相似度不高，布局、样式、内容或视觉表现仍有明显差异。
- 2 分：核心问题修复完成，且与参考图高度一致，对应 UP 指令也完全实现。
- 同一题多个产物都具备 2 分条件时，只能选最佳一个为 2 分，其余统一降为 1 分。

## 操作流程

1. 查看图片产物，理解参考图的页面结构、主要视觉元素和最终页面效果。
2. 查看问题修复描述，明确修复前的问题和模型应完成的具体修复。
3. 打开修复后的网页产物，从首屏浏览到页面底部。
4. 检查网页是否能正常加载；一直加载或无法展示直接评 0 分。
5. 检查问题是否真正修复；核心问题仍存在直接评 0 分。
6. 问题已修好后，再比较参考图还原度；差异明显评 1 分，高度一致才进入 2 分候选。
7. 如果同题有多个 2 分候选，综合修复完成度与还原度选最优一个为 2 分，其余为 1 分。
8. 提交前复核是否误把废弃题纳入普通评分，是否误给多个 2 分。

## 废弃规则

- 问题描述指出的错误在修复前产物中并不存在，直接废弃。
- 题目本身存在明显问题，例如 Prompt 与参考图不对应、参考图异常、截图顺序错误或信息缺失，直接废弃。
- 参考图本身有问题，且题目要求按这张有问题的参考图继续修复，直接废弃。
- 非文字题中，Prompt 没有问题描述，也没有提供可用参考图，直接废弃。

## 易错点

- 不要只看页面美观度；核心修复没有完成时必须 0 分。
- 不要只看问题修复；修好了但不像参考图通常只能 1 分。
- 不要给多个 2 分；同题多个高质量候选也必须唯一判定。
- 不要把题目异常当成 0 分；命中废弃规则时应废弃。
- 需要从首屏到底部检查页面，避免只凭局部截图判断。
- 对应 UP 指令没有完全实现时不能评 2 分。

## 理由话术

- 理由应短、自然、中文口语化。
- 可说明“问题未修复”“页面无法加载”“问题已修复但还原差异明显”“修复完成且还原度高”“命中废弃规则”。
- 多候选时可说明“同题只能保留最佳 2 分，其他候选降为 1 分”。

## 问卷知识点

- 评分前先判断废弃。
- 页面加载不出来或一直加载为 0 分，不是废弃，除非题目本身异常。
- 问题未修复为 0 分。
- 问题修复但还原度不高为 1 分。
- 问题修复且参考图还原度高、UP 指令完全实现才可评 2 分。
- 同一题多个 2 分候选时只能保留最佳一个 2 分。
